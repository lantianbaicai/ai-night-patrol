# 个人机会决策引擎

夜巡 V4 不再只回答“什么正在变热”，还要回答三个更难的问题：

1. 这个机会是否适合当前的杨恒？
2. 为什么适合或不适合？
3. 7 天、30 天后，原判断是否被真实结果支持？

## 两套分数必须分开

- **原报告分**：保留夜巡报告对市场信号的原始评分，不做追溯修改。
- **个人匹配分**：根据现有资产、能力、渠道和证据成熟度重新计算。

热点很高但个人匹配很低时，不进入构建队列。个人匹配很高也不等于已经有付费需求，它只表示验证成本更低。

## 个人匹配公式

画像配置位于 `data/opportunity_profile.json`，默认权重如下：

| 维度 | 权重 | 回答的问题 |
|---|---:|---|
| 资产复用 | 35% | 是否已经有可运行项目、样本或代码可直接复用？ |
| 能力匹配 | 25% | 是否具备低成本完成验证的能力？ |
| 渠道触达 | 15% | 是否能接触真实目标用户，而不只是看到热点？ |
| 证据成熟 | 25% | 是否存在直接付费、外部用户和重复信号？ |

每个维度先归一化为 0-100，再按权重求和：

```text
个人匹配分 = 资产复用×35% + 能力匹配×25% + 渠道触达×15% + 证据成熟×25%
```

- `>= 75`：进入构建，但仍需先验证真实需求。
- `55-74`：继续验证，不扩大投入。
- `< 55`：暂缓。
- 未分类信号默认 `0` 分，不让模型自行脑补映射。

## 7 天与 30 天复核

所有 `data/decision_ledger.json` 中的判断都会自动生成两个复核节点：

- **7 天**：检查是否产生访谈、试用、回复、演示请求等早期信号。
- **30 天**：检查是否产生持续使用、面试、成交、复购或明确否定。

真实结果单独保存在 `data/decision_outcomes.json`。初始文件为空，界面必须如实显示“完成结果为 0”。

记录结果时使用：

```powershell
python tools/record_decision_outcome.py night-patrol-career-proof 7 `
  --result mixed `
  --evidence "一位招聘方打开作品页并追问实现方式" `
  --note "出现兴趣，但还不是面试"

python tools/build_dashboard_data.py
```

结果类型：

- `confirmed`：判断成立。
- `mixed`：部分成立。
- `reversed`：原判断被推翻。
- `no-signal`：在复核窗口内没有有效信号。

工具强制要求填写具体证据，不接受空结果。相同判断和窗口再次记录时会更新旧记录，不会重复计数。

## 当前边界

- 画像是可替换配置，不是永久人格判断。
- GitHub Star、运行次数和报告数量都不能替代客户或招聘反馈。
- “适合构建”不等于“市场已经验证”。
- 被否决、停止的判断同样进入复核队列，用来检查夜巡是否错杀机会。
