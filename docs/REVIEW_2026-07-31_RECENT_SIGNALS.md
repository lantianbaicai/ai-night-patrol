## 对原夜巡结论的修正

最近几份日报中的这些表述需要降级为“待验证假设”：

- “7 天真能出一个”只说明原型可行，不说明能稳定交付。
- “30 天内收费”没有客户名单、触达路径和付款证据支撑。
- “国内市场空白”需要系统竞品检索，不能仅凭 GitHub 榜单判断。
- “Agent Skills 是新时代 App Store”是有启发性的类比，不是收入模型证据。
- “开源替代是最确定赚钱路径”忽略了数据采购、许可证、运维、获客和差异化成本。
- “闲鱼 AI 工具箱最快变现”已被验证账本否定；闲鱼当前只适合作为服务渠道实验。

## 与当前工作的组合决策

### P0：工程文档助手 + OfficeCLI

这是最近信号里唯一已经变成可运行集成的方向，也最能利用工程经历。下一步不是继续加功能，而是补齐 10 份脱敏样本、人工标注、误报/漏报和一位外部使用者反馈。

### P0：夜巡 V3

夜巡本身应继续成为 Agent Harness 作品。可借鉴 World Monitor 的不是视觉地图，而是：

- 来源覆盖与新鲜度；
- 每个结论的支持范围；
- 程序化数据输出；
- 失败状态和维护状态；
- 预先判断与到期复核。

验证账本和公开部署已经完成；外部网络访问确认、招聘反馈和判断到期复核仍是当前最大缺口。

### P1：工程文档预审 Skill

只发布一个垂直 Skill。它需要包含安装检查、样本文档、结构化结果、失败回退和跨环境测试。先证明第二个 Agent 环境能够复现，再谈 Skill 市场或收费。

### P1：Local-first 作为产品约束

不单独 Fork Meetily。把“原文件留在本机、结构化规则优先、模型结果需人工确认”写进工程文档助手的部署与演示口径。

### 暂缓

OpenSEO 中文版、Meetily 私有部署、OpenCut、金融 AI 和通用 Agent 网关继续观察。它们有热度，但都不能增加当前作品闭环的证据密度。
