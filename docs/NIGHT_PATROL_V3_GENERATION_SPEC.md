# AI 夜巡 V3 生成规范

## 目标

夜巡不是“热点项目推荐器”，而是机会假设生成器。每轮报告必须把技术热度、客户需求、付费证据、个人能力匹配和下一步验证分开，不允许用 GitHub star、媒体报道或模型判断互相替代。

## 判断纪律

1. GitHub star 只能证明开发者关注度，不能证明客户、收入或留存。
2. “客户明确”只有在出现客户需求、采购、招聘职责、用户访谈或真实服务订单时才能标记为是。
3. “30 天收费”只有在存在直接付费证据、明确询价或可触达试用者时才能标记为是。
4. “7 天 Demo”必须写出依赖。涉及反爬、登录态、硬件、私有数据、复杂许可证或模型训练时不能直接标记为是。
5. “国内空白”“零竞品”“最快变现”必须有系统竞品检索或访谈支持，否则视为未经验证的假设。
6. 每轮最多保留 5 个候选。证据不足时宁可输出 1 个，也不能凑数。
7. 抓取失败必须显示为失败，不能用旧数据或模型常识补成“已采集”。
8. 每个候选必须写明支持什么、不支持什么、下一步验证和停止条件。
9. 标题分数必须等于五项指标中 `✅` 的数量，不能把候选序号写成分数。
10. 没有直接客户证据时，不得建议开发新的付费产品；最多进入低成本验证。
11. 新方向只有在直接服务当前 P0 项目或存在真实客户需求时才能“进入构建”。
12. 目标值不是当前完成值。当前样本、测试、外部用户、准确率、部署状态等项目事实只能来自 `data/project_facts.json`；文件未记录时写未知，不得根据计划或旧报告补全。

## 选题雷达

### 候选名称（X/5）
标题不要写候选序号。X 必须等于下方五项中 ✅ 的数量。
- 信号：一句话说明本轮观察，不写营销结论
- 来源：一手来源标题（URL）；第二来源（URL）
- 客户明确：✅/❓/❌ + 证据
- 7天Demo：✅/❓/❌ + 依赖与边界
- 30天收费：✅/❓/❌ + 直接/间接/无付费证据
- 复用资产：✅/❓/❌ + 可以复用的现有代码、样本或能力
- 长期壁垒：✅/❓/❌ + 数据、渠道、领域知识或没有壁垒
- 当前项目增益：说明它如何增强夜巡、工程资料预审台、垂直工程 Skill 或求职证据；没有则写“无”
- 支持：这些来源能够支持什么判断
- 不支持：这些来源不能支持什么判断
- 行动：进入构建/继续验证/暂缓/否决 + 一个最小验证动作
- 停止条件：什么结果出现时不再投入
