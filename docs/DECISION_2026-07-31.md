# 夜巡决策记录 · 2026-07-31

这份记录不是热点摘要，而是把最近三天夜巡信号转换成项目取舍。

## 当前证据

- 截至 2026-08-01，夜巡本地累计分析 340 份摘要，公开作品集已包含全部 111 份去重报告，待发布为 0；这些数字不是用户数或付费数据。
- 最近 30 份报告中，Agent Skills 出现 22 次，开源 SaaS 替代与 Agent 基础设施各出现 23 次。
- 7 月 29 日至 31 日，OfficeCLI、Meetily、Open-SEO、Agent Skills 连续出现。
- 最新报告可审计性为 80/100；主要缺口是部分原始报告没有保留可点击来源链接。

## 项目取舍

| 优先级 | 方向 | 决策 | 原因 |
|---|---|---|---|
| P0 | 工程文档助手 + OfficeCLI | 继续开发 | 同时利用工程经历、文档处理和 AI 工具集成能力，能形成真实样本、评测和客户 Demo |
| P0 | 夜巡 V3 | 继续产品化 | 它本身就是长程 Agent、证据追踪、失败恢复和机会判断的作品，不只是日报生成器 |
| P1 | Agent Skill | 只验证 1 个垂直 Skill | 做“工程文档预审”或“机会证据审计”这类有独特数据和流程的 Skill，不再批量包装通用天气、摘要类工具 |
| P2 | 闲鱼 | 作为获客渠道试验 | 订单增长是真信号，但低客单和同质化也明显；先卖服务，不先做“闲鱼工具箱” |
| 观察 | Open-SEO 中文版 | 暂缓 | 数据源、平台规则和长期维护成本尚未验证 |
| 观察 | Meetily 私有部署 | 暂缓 | 有企业价值，但当前缺少一手客户和部署运维案例 |
| 放弃本轮 | OpenCut、Agent 网关、通用基础设施 | 不投入 | 体量大、竞争强，与当前作品闭环关系弱 |

## 为什么这样组合

三项资产可以互相提供证据：

1. 夜巡发现并连续验证 OfficeCLI 信号。
2. 工程文档助手把信号变成可运行集成，并用真实与公开样本文档测试。
3. 夜巡仪表盘记录决策依据、风险和结果，形成可复盘的 Agent Harness 案例。
4. 三份定向简历只引用已经能够展示和复核的证据。

这比同时启动闲鱼工具箱、Open-SEO、会议助手和多个通用 Skill 更有价值，因为每一步都在增加同一份作品的可信度。

## 接下来 14 天的成功标准

- 工程文档助手：扩展到至少 10 份脱敏样本，建立人工标注清单，记录命中、误报和漏报。
- 夜巡：每周只选 3 个候选机会，预先写下判断，7 天后回看结果，开始统计判断命中率。
- 公开演示：录制一段 60 至 90 秒视频，展示“夜巡发现信号 → 文档助手落地 → 证据回写仪表盘”。
- 求职：用三份定向简历分别投递对应岗位，记录回复率，不把投递数量当作品成效。
- Skill：只发布一个与工程文档预审相关的可安装版本，并记录真实安装、运行失败和反馈。

## 停止条件

- 没有真实样本或人工复核数据时，不宣称准确率。
- 没有外部用户时，不把本地报告数写成用户量、客户量或市场验证。
- 某个新方向连续出现，只代表值得研究；只有与现有能力匹配且能形成验证闭环，才进入开发。
